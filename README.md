# Nightingale Recruit

Healthcare Recruitment Outreach Automation System for USA Healthcare Professionals.

## Tech Stack

- Next.js 16 (App Router)
- TypeScript
- Tailwind CSS v4 + shadcn/ui
- Firebase (Auth, Firestore, Storage)
- **Apollo.io** (prospect search, LinkedIn enrichment)
- Nodemailer (SMTP email)
- React Hook Form + Zod
- TanStack Table, Recharts, Framer Motion

## Getting Started

### 1. Firebase Setup

1. Create a Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
2. Enable **Email/Password** authentication
3. Create a **Firestore** database
4. Enable **Storage**
5. Generate a **service account key** (Project Settings → Service Accounts → Generate new private key)

### 2. Environment Variables

Copy `.env.local.example` to `.env.local` and fill in:

```bash
cp .env.local.example .env.local
```

Required variables:
- `NEXT_PUBLIC_FIREBASE_*` — from Firebase project settings
- `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY` — from service account JSON
- `APOLLO_API_KEY` — from [Apollo.io Settings → API](https://app.apollo.io/#/settings/integrations/api) (server-only)
- `CRON_SECRET` — random string for automation cron endpoint

### 3. Deploy Firebase Rules

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage
```

Or copy `firestore.rules`, `firestore.indexes.json`, and `storage.rules` into your Firebase project manually.

### 4. Install & Seed

```bash
npm install
npm run seed
npm run dev
```

`npm run seed` creates **admin/recruiter logins and default settings only** — not mock candidates.

To remove old seed candidates from a previous run:

```bash
SEED_CLEAR_MOCK_CANDIDATES=true npm run seed
```

Open [http://localhost:3000](http://localhost:3000)

## Apollo.io — Real Candidate Data

Candidates are imported from Apollo, not generated by seed.

### Workflow

1. Go to **Find Prospects** in the sidebar
2. Set filters (job title, state, city, employer domain)
3. Click **Search Apollo** — preview results (names obfuscated until enrich)
4. Select rows → **Enrich selected** — reveals LinkedIn URL, email, phone (uses Apollo credits)
5. **Import to CRM** — saves to Firestore with `source: apollo` and dedup by Apollo ID / email

### Enrich existing candidate

On any candidate profile, click **Enrich from Apollo** to refresh LinkedIn and contact data using their email, LinkedIn URL, or Apollo ID.

### API routes (server-side)

- `POST /api/apollo/search`
- `POST /api/apollo/enrich` (max 10 IDs per call)
- `POST /api/apollo/import`
- `POST /api/apollo/enrich-candidate`

## SMTP Configuration

1. Sign in as Admin
2. Go to **Settings**
3. Enter your SMTP host, port, credentials
4. Save settings

Emails are sent via `/api/email/send` and automated follow-ups via `/api/automation/run` or cron.

## Automation Cron

On Vercel, `vercel.json` schedules two jobs (both protected by `CRON_SECRET`):

- `/api/automation/cron` — daily at 08:00 UTC — sends due follow-up emails (Day 1/3/7/14, stops on reply).
- `/api/sourcing/cron` — daily at 07:00 UTC — runs all enabled Auto-Sourcing rules.

Both expect:

```
Authorization: Bearer <CRON_SECRET>
```

Manual triggers: **Followups** page → "Run Automation Now"; **Auto-Sourcing** page → "Run now" / "Run all enabled".

## Auto-Sourcing (scheduled candidate sourcing)

Admins define **sourcing rules** (saved Apollo searches) on the **Auto-Sourcing** page. Each rule stores job titles, location, a per-run cap, an optional assigned recruiter, and an auto-enroll toggle.

When a rule runs (manually or via cron) it:

1. Searches Apollo for matching people.
2. Enriches them (emails, phones, LinkedIn) in batches.
3. Imports new candidates into Firestore, **skipping duplicates** by Apollo ID and email.
4. Auto-tags each candidate by role, state, and `auto-sourced`.
5. Optionally enrolls imported candidates in the Day 1/3/7/14 follow-up sequence (requires an assigned recruiter).

Rule run stats (last run time, last/total imported) are tracked per rule. Works in Apollo sandbox mode for testing without a paid plan.

Endpoints:
- `GET /api/sourcing` (via client service), `POST/PATCH/DELETE /api/sourcing` (admin)
- `POST /api/sourcing/run` (admin; optional `{ "ruleId": "..." }`)
- `GET /api/sourcing/cron` (cron secret)

## Hands-off automation

Configured on **Settings → Automation**:

- **Auto-assign** — imported candidates are distributed across active recruiters via least-loaded round-robin instead of all landing on the importer.
- **Auto-enroll on import** — imported candidates with an email are automatically enrolled in the Day 1/3/7/14 follow-up sequence (Day 1 goes out on the next engine run).
- **Daily send cap** — caps automated emails per day across all sequences (0 = unlimited).
- **Business hours** — restricts automated sends to a configurable hour window (server time).

### Reply detection (auto-stop)

Point your email provider's inbound parse webhook at:

```
POST /api/email/inbound?secret=<INBOUND_SECRET>
```

Supported payloads: JSON (Postmark-style) and multipart form (SendGrid / Mailgun). When a known candidate replies, they're marked **Replied**, their sequence is stopped, the latest outreach is flagged replied, and the assigned recruiter gets an activity entry.

### Open / click tracking

Every automated and manual email gets a 1×1 open pixel (`/api/track/open`) and links wrapped through `/api/track/click`. Opens/clicks accumulate on the outreach record. Requires `NEXT_PUBLIC_APP_URL` to be set to your public domain.

### Unsubscribe & compliance

Every email includes a signed unsubscribe link (`/api/unsubscribe`). Unsubscribing sets `optedOut`, stops the sequence, and blocks all future automated and manual sends (CAN-SPAM compliant). Bounced addresses (`emailBounced`) are skipped by the engine.

## CRM experience

- **Engagement analytics** — open/click/reply rates on Dashboard and Analytics; per-email stats on candidate profiles
- **Notification center** — bell in header for replies, assignments, and follow-ups sent (live Firestore)
- **Pipeline Kanban** — drag candidates across stages at `/pipeline`
- **Command palette** — `Cmd/Ctrl+K` to jump to pages, candidates, and quick actions
- **Tasks widget** — today's tasks on the dashboard
- **Saved filter views** — save and reuse candidate filter combos
- **Dark mode** — toggle in the header
- **Conversation thread** — inbound/outbound messages on candidate detail
- **CSV import wizard** — column mapping + duplicate preview before import
- **AI assist** — draft email, summarize candidate, suggest next step (`OPENAI_API_KEY` optional; template fallback)
- **Duplicate merge** — admin "Find Duplicates" on Candidates
- **SMS** — `POST /api/sms/send` via Twilio (optional env vars)
- **Interview scheduling** — "Schedule Interview" when status is Interested

Deploy Firestore indexes: `firebase deploy --only firestore:indexes`
